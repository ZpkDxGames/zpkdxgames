# DESIGN.md — ZpkDxGames Profile Dashboard v2.0

Target: `https://github.com/ZpkDxGames/zpkdxgames` (special profile repository, renders on `https://github.com/ZpkDxGames`)
Vibe: Minecraft plugin engineer / Java backend. A live server control panel: dark, dense, glowing emerald and cyan, monospaced, redstone circuit accents.

---

## 1. Architecture

```
config/profile.json ──┐
                      ├─► scripts/build_assets.py ──► assets/*.svg   (custom, self-rendered, animated)
GitHub REST/GraphQL ──┤                               metrics/*.svg  (stubs only, created if missing)
Modrinth / Spiget /   │
bStats (optional) ────┘

lowlighter/metrics action ─────────────────────────► metrics/*.svg   (isocalendar, skyline, languages,
Platane/snk action ────────────────────────────────►                  habits, activity, lines, ...)

.github/workflows/profile-sync.yml  runs all of the above every 8 h (+ manual + on config change)
                                    and commits assets/ + metrics/ in ONE commit.
README.md  references only relative paths: assets/*.svg and metrics/*.svg
```

Design decisions and why:

| Decision | Reason |
|---|---|
| Custom SVGs generated by a stdlib-only Python script instead of third-party stat cards | Public card hosts (github-readme-stats on Vercel, etc.) are rate-limited and go down. Files committed to the repo never break. |
| Banners, loadout chips and the footer are generated from `config/profile.json` | One file to change name, tagline, stack chips and section titles. Colors come from the same palette everywhere. |
| `lowlighter/metrics` with `output_action: none`, then copy and commit once | Avoids a push race between multiple steps; one atomic commit per run. |
| Stubs committed up front (`AWAITING FIRST SYNC`) | The README never shows broken-image icons before the first Action run. |
| Each metrics step is `continue-on-error: true` | One flaky plugin (skyline and in-depth languages are the heaviest) never blocks the rest. Last good render is kept. |
| SVGs embedded with `<img>` | GitHub strips inline `<svg>`, `<style>` and `<script>` from READMEs but renders SVG files in `<img>`. SMIL and CSS animations inside those files run; scripts and external fonts do not. |
| Relative image paths | Resolve correctly on the profile page and in the repo view, no cache-busting CDN in between. |

## 2. Layout grid

GitHub's sanitizer allows `<table>`, `<tr>`, `<td width>`, `<div align>`, `<img width>`, `<kbd>`, `<a>`, `<sub>`, `<details>`, `<picture>`. It strips `style`, `class`, `<style>`, `<svg>`, flexbox and grid. So:

- **Flex simulation** = `<div align="center">` for centering and `<table>` with `width="NN%"` cells for columns. Markdown inside cells needs a blank line after the opening `<td>` and before `</td>`.
- Every full-width image uses `width="100%"`. Master canvas width is **1000 px** for all custom SVGs (viewBox 1000 wide), which GitHub scales to its ~830 px content column with identical proportions.
- Metric cards (lowlighter) have their own intrinsic width; in the 2-column table they are forced to `width="100%"` of a 50% cell.

## 3. Color palette

All values live in `config/profile.json → palette` and are consumed by `build_assets.py`.

| Role | Hex | Usage |
|---|---|---|
| Background (charcoal) | `#0d1117` | Canvas of every custom SVG (matches GitHub dark) |
| Panel | `#111820` | Cards, section banners |
| Panel alt | `#0f151c` | Window chrome, console panel |
| Grid / hairline | `#16202b` | Animated background grid |
| Border | `#1f2a37` | 1 px card strokes |
| Text | `#e6edf3` | Primary text |
| Muted | `#8b949e` | Labels, units, secondary text |
| **Emerald (telemetry accent)** | `#00ff66` | Primary glow, headlines, level-4 heatmap, SERVER ONLINE |
| Lime (Minecraft green) | `#55ff55` | Streak tile, command lines (MC color `§a`) |
| Dark green (Minecraft) | `#00aa00` | Dim circuit traces (`#0e3b1f` as unlit redstone dust) |
| GitHub green | `#2ea043` | Divider nodes, heatmap level 3 is `#26a641` |
| **Electric cyan (tech highlight)** | `#00f0ff` | Section index chips, commits tile, INFO/PUSH log tags |
| Gold (MC `§6`) | `#ffaa00` | Stars tile, OFFLINE pill, ISSUE/STAR tags |
| Redstone | `#ff3b30` | One accent pulse in the header circuit, nothing else |

Heatmap ramp (levels 0–4): `#161b22 → #0e4429 → #006d32 → #26a641 → #00ff66` (the same five colors are passed to the snake via `color_dots`).

Rule: emerald and cyan are glow colors (used with the blur filter and animation); lime and gold are flat accent colors. Never use more than two accent colors inside one card.

## 4. Typography and icon language

- **Font stack** (SVG `font-family`): `ui-monospace, SFMono-Regular, 'JetBrains Mono', Menlo, Consolas, 'Liberation Mono', monospace`. External webfonts cannot load inside `<img>` SVGs, so the stack relies on system monospace fonts. Layout math assumes **0.602 em per glyph** (that is how the typewriter clip widths are computed), which holds for all of the fonts above within ±3%.
- **Scale:** name 64/800 · section title 24/800 + 3 px tracking · KPI value 40/800 · log lines 12.5 · labels 11 uppercase with 1.8 px tracking · body 13–14.
- **Icon language:** pixel-art glyphs (8×8 bitmaps, 3 px cells) for the four KPI cards (plugin block, star, commit, flame), square "redstone repeater" nodes at circuit corners, block cursor `▌` blinking at 1.1 s, status dot pulsing at 1.6 s.
- **Voice:** Minecraft server console. `[INFO]`, `Done (0.42s)!`, `TPS 20.0`, `latest.log`, `/gamerule keepInventory true`. Section commands are real-looking shell/console commands (`cat profile.yml`, `tail -f latest.log`, `plugins --list`, `timings report`).

## 6. Animation inventory (all SMIL, no scripts)

| Element | Effect | Mechanism |
|---|---|---|
| Header boot log | Typewriter, one glyph per 28 ms, cursor follows, final cursor blinks | `animate width` on `clipPath rect` + `animate x` on cursor, `calcMode="discrete"` with keyTimes |
| Header grid | Slow diagonal pan | `animateTransform translate` 10 s loop |
| Circuits, divider, footer | Light pulse travelling along wire | `stroke-dashoffset` loop |
| Status pills | Pulse | `r` + `opacity` loop |
| Cards, chips, log lines | Staggered fade-in | `opacity values="0;0;1"` with keyTimes carrying the delay |
| Heatmap | Column-by-column reveal | same technique, 30 ms per column |

Safety property: every base attribute is the final visible state (clip width = full, opacity = 1), so a renderer without SMIL support shows the finished image instead of a blank one.

## 7. Failure modes and degradation

| Failure | Result |
|---|---|
| No `METRICS_TOKEN` secret | Metrics steps skipped; stubs remain; custom assets still refresh using the default `github.token` (REST + GraphQL work for public data). |
| A metrics step errors or times out | `continue-on-error`; previous committed render stays. |
| GitHub API unreachable inside the script | `OFFLINE SNAPSHOT` pill, values show `n/a`. |
| Modrinth / Spiget / bStats down or misconfigured | That tile shows `n/a`. |
| Nothing changed | No commit created. |
| Bot commits | Use `GITHUB_TOKEN`, so they do not retrigger the workflow (no loops). |

## 8. Extension points

- Add a stack chip: edit `stack` in `config/profile.json`, commit; the `push` trigger regenerates `stack.svg`.
- Add a section: append to `sections`, add the `<a id>` + `<img>` to `README.md`.
- Swap accent colors: edit `palette`; everything custom recolors. (lowlighter cards keep their own theme.)
- Show a different metrics card: add a step in `profile-sync.yml` with a unique `filename`, add its name to `METRIC_STUBS` in the script, reference `metrics/<name>.svg` in the README.
- Pin vs. most-starred repos: in the repositories step replace `plugin_repositories_starred: 6` with `plugin_repositories_pinned: 6` (renders nothing if no repos are pinned).
